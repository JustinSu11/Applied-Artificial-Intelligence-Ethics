# LAYER 1: LEARN IT

## The big idea
Noise has the **same absolute size for every group**, but the
**same noise is a much bigger share of a small number.** So
majority groups barely notice; small communities can be badly
distorted.

**Hook:** A **±10 wobble** on a 6,000-person count is dust.
On a 111-person count it's a **9% error.**

## Why the census example
- The census drives **resource distribution, school locations,
  public health funding, and even political power.**
- The **US Census Bureau** began using differential privacy,
  adding noise so individuals are hard to identify.
- Risk without noise: in a tiny rural town, an exact count of a
  small group can **identify individuals** and enable targeted
  discrimination.
- Cost with noise: **real-world consequences** for the
  communities represented (a group counted too low may get too
  little funding).

## The setup (code walk-through)
1. **Libraries:** pandas, NumPy, Matplotlib.
2. **Mock data:** `np.random.seed(531)`, **10,000 people** with
   Ethnicity, Age, Income, Location, Education, drawn from set
   proportions.
3. **Baseline ethnicity counts (verified):**
   White 5,991 · Hispanic 1,780 · Black 1,217 · Asian 594 ·
   Other 307 · **Native American 111** (the smallest group).
4. **`apply_laplace_mechanism(counts, epsilon, sensitivity=1)`:**
   for each count, add noise from **Laplace(0, sensitivity/epsilon)**,
   and clip at 0 (`max(0, value + noise)`).
5. **`pct_error(orig, priv)`:** `(priv - orig) / orig * 100`
   (returns 0 if orig is 0).
6. **Epsilons tried:** **0.1, 0.5, 1.0.**
7. **Histogram function:** repeat the mechanism **1,000 times**,
   collect every relative error, plot one histogram per epsilon.

## The key insight: relative error = noise / count
- For Laplace noise with scale **b = sensitivity / epsilon**, the
  **typical absolute error is about b.**
- So **typical relative error is about b / count.** (Check: it
  matches the simulation.)

| Group | e = 0.1 (b = 10) | e = 0.5 (b = 2) | e = 1.0 (b = 1) |
|---|---|---|---|
| White (5991) | 0.17% | 0.03% | 0.02% |
| Hispanic (1780) | 0.56% | 0.11% | 0.06% |
| Black (1217) | 0.82% | 0.16% | 0.08% |
| Asian (594) | 1.68% | 0.34% | 0.17% |
| Other (307) | 3.26% | 0.65% | 0.33% |
| **Native American (111)** | **9.01%** | 1.80% | 0.90% |

**Hook:** Same noise, **smaller denominator**, bigger error.

## The histograms (1,000 samples, all groups pooled)
- **e = 0.1:** wide spread. Worst errors reach roughly **60%+**
  (my 1,000-sample run: max about **66%**, mean absolute error
  about **2.7%**). Lecturer said "almost 60%."
- **e = 0.5:** errors stay **under about 15%** (my run: max about
  **13.9%**). Matches the lecturer.
- **e = 1.0:** tightest (my run: max about **6.2%**).
- Pattern: **smaller epsilon = fatter tails = more lost
  utility.**

## Common confusions
- **Noise isn't bigger for minorities.** It's the **same size**;
  it just matters more against a small count.
- **Clipping at 0** (`max(0, ...)`) keeps counts non-negative but
  slightly **biases** small counts upward (my addition).
- Smaller epsilon = **more privacy**, not more accuracy.
- This lab is not about coding DP. It is about understanding
  **the cost of protecting privacy.**

## Big picture recap
- DP protects individuals by adding noise scaled to
  sensitivity/epsilon.
- Strong privacy (small epsilon) -> large distortions.
- Small communities suffer most, which has **real policy
  consequences** (funding, representation).
- Choosing epsilon is a **judgment call** you must justify.

## Answers
1. sensitivity / epsilon (b = 1/e for counts).
2. 0.1 (more noise).
3. Same absolute noise (about 10), but 10/111 is about 9% while
   10/5991 is about 0.17%.
4. b = 2 -> about 2/50 = 4%.
5. One person joining or leaving changes the count by at most 1.

   privacy). Halve: double the noise.

    (healthcare small epsilon, low-stakes analysis larger);
    justify using the error you can tolerate for the smallest
    group.
